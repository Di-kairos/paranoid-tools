# Paranoid Tools — инструкция по запуску

Пять CLI-инструментов приватности для macOS. Каждый делает **одну** вещь и честно
говорит, где гарантий нет — не обещает «100% безвозвратно» там, где SSD и macOS
могут оставить копию.

> English version: [GUIDE.md](GUIDE.md).

## Установка (одна команда)

```bash
git clone https://github.com/Di-kairos/paranoid-tools
cd paranoid-tools
bash install.sh
```

Ставит все 5 инструментов и лаунчер `paranoid` в `~/.local/bin` (обычно уже в `PATH`; если
нет — установщик подскажет, как добавить). Снести всё: `bash install.sh --uninstall`.

На свежем клоне каждый инструмент тянется из подписанного релиза: скачанный установщик
инструмента и его бинарь проверяются по подписи и контрольной сумме до запуска (сам верхний
`bash install.sh` ты запускаешь руками, прочитав его).

## Обновление

Выбери в лаунчере пункт **6) Обновить** (пока только в macOS-лаунчере — Windows-версия
по-прежнему отправляет запускать установщик руками). Он перезапустит `install.sh` из твоего
клона, а тот подтянет свежий релиз каждого инструмента и перезапишет бинарь на месте. Релизы,
скачанные с GitHub, проверяются по Ed25519-подписи; инструмент, который уже лежит в клоне,
ставится оттуда как есть — то есть результат зависит от того, на какой клон ты указал.

Спросит явное `yes`, покажет точный каталог, код которого сейчас выполнится, и не угадывает:
не нашёл клон — так и скажет, а не пойдёт качать что-то сам. Лаунчер помнит клон, из которого
ставили в прошлый раз; переопределить — `PARANOID_SRC=/путь`. Учти: уже запущенный процесс
лаунчера продолжает работать на старом коде, пока не выйдешь и не запустишь заново.

То же самое руками:

```bash
cd paranoid-tools
git pull            # подтянуть свежий клон (лаунчер + установщик)
bash install.sh     # переустановить все инструменты на последние подписанные релизы
```

Проверить версию: `securetrash version` (или `--version` у любого инструмента).

**Важно:** если обновился инструмент, у которого поменялось поведение во время работы (напр.
`securetrash vault` стал монтировать том видимым в Finder), уже открытая сессия осталась
на старом коде. Переоткрой её новым бинарём: `securetrash vault close` → `securetrash vault
open`.

## С чего начать — запусти `paranoid`

Главная точка входа. Одна команда открывает дашборд со статусом и меню поверх всех
пяти инструментов:

```bash
paranoid
```

Сверху — живой статус (обновляется при каждом возврате в меню):

```
Сейф:        ● ОТКРЫТ (/Volumes/SecretVault)   ⚠ под угрозой, пока открыт
FileVault:   ● ВКЛ
vaultwatch:  ● активен
```

- **Сейф** — открыт он или закрыт. Открытый помечается «под угрозой»: пока он
  смонтирован, данные доступны любому, кто за твоим Mac.
- **FileVault** — включено ли системное шифрование диска.
- **vaultwatch** — сторожит ли сейчас открытый сейф (`активен`) или сессий нет (`нет сессий`).

Ниже — меню (выбор по цифре). Пункты сгруппированы в подменю, чтобы верхний уровень
оставался коротким; «ПАНИКА» вынесена наверх ради скорости — в одно нажатие:

```
1) Статус        — полная read-only проверка (что реально защищает на твоём железе)
2) 🔒 ПАНИКА     — спрятать и запереть всё, жёсткий режим (мгновенно, без подтверждения)
3) Сейф ▸        — подменю работы с шифрованным сейфом
4) Блокнот ▸     — подменю эфемерных черновиков (ghostdraft)
5) Секреты ▸     — подменю разбить / собрать секрет (seedsplit)
6) Обновить      — подтянуть последние подписанные релизы и переустановить
0) Выход
```

Подменю **`3) Сейф ▸`**:

```
1) Открыть / Закрыть / Создать  — метка меняется по текущему состоянию сейфа
2) Очистить                     — гарантированно стереть всё содержимое (см. ниже)
                                  (это `vault reset`, а НЕ `securetrash empty`)
3) Уничтожить                   — снести сейф целиком (необратимо)
4) Охрана                       — взять открытый сейф под охрану / снять (vaultwatch, toggle)
0) Назад
```

vaultwatch живёт именно здесь, потому что сторожит **открытый** сейф — это его TTL-охрана
от Spotlight, Time Machine и облака.

Подменю **`4) Блокнот ▸`** (два пункта): `1) заметка` (написать/править/скопировать —
на выходе исчезает; копирование в буфер с авто-очисткой ~20 секунд встроено) и `2) показать буфер`.
Подменю **`5) Секреты ▸`**: `разбить` / `собрать`.
У каждого подменю есть `0) Назад`.

Лаунчер секретов не хранит и своей крипты не добавляет: он запускает те же пять
подписанных CLI и показывает их вывод как есть — со всеми оговорками и вердиктами.
Всё, что делает меню, доступно и напрямую — команды ниже.

## У меня есть seed phrase. Проведи за руку.

Полный цикл одного ценного секрета, от начала до конца. Так же работает с приватным
ключом, кодом восстановления, паролем, утечку которого не пережить. Десять минут,
шесть шагов.

Сначала реши, твой ли это инструмент вообще: [THREAT-MODEL.ru.md](THREAT-MODEL.ru.md)
прямо говорит, от чего защищает, а от чего нет.

**1. Проверь, что реально защищает тебя на этой машине.**

```bash
securetrash check
```

Прочитай вердикт. Если FileVault выключен — сначала включи (Системные настройки →
Конфиденциальность и безопасность → FileVault). Всё дальнейшее исходит из того, что
диск зашифрован; без этого сейф — запертая шкатулка в открытой комнате.

**2. Создай сейф.**

```bash
securetrash vault create
```

Спросит размер и пароль. Пароль — это всё: он нигде не хранится, и сброса нет.
Сейф — шифрованный контейнер (`~/SecureVault.sparsebundle`); открытый, он монтируется
в `/Volumes/SecretVault`.

**3. Запиши фразу — внутрь сейфа.**

```bash
securetrash vault open
nano /Volumes/SecretVault/seed.txt
```

Обычный файл внутри шифрованного контейнера: закрыл сейф — на диске шифротекст. Это
твоя постоянная копия. `ghostdraft new` для этого НЕ подходит — он ровно про обратное:
эфемерный черновик, который шредится при выходе из редактора (правильно для секрета,
который записал и один раз передал; фатально для того, который хотел сохранить).

**4. Охраняй сейф, пока он открыт.**

Пока сейф смонтирован, его содержимое читается любым, кто за твоим Mac. `vaultwatch`
перекрывает те каналы утечки, до которых дотягивается (индексация Spotlight,
Time Machine), и честно называет те, до которых не дотягивается (запущенные облачные клиенты).
Подключи его один раз — и `vault open`/`close` сами будут поднимать и снимать сторожа:

```bash
vaultwatch install-hooks
```

Добавить таймер, который закроет забытый сейф (сейф с открытыми из него файлами он
принудительно не отмонтирует — честно, не магия):

```bash
vaultwatch start --ttl 30m /Volumes/SecretVault
```

**5. Настрой паническую кнопку — до того, как понадобится.**

```bash
panic status                 # что произойдёт прямо сейчас
panic now                    # боевой режим: отмонтировать тома, очистить буфер, запереть экран
panic hotkey install         # глобальный хоткей (cmd+alt-p) → panic now, из любого приложения
```

`panic hotkey install` требует skhd (`brew install skhd`) — крошечный демон хоткеев;
`panic hotkey status` покажет текущее состояние, `panic hotkey uninstall` снимет только
тот блок, которым управляет сам panic.

**Три способа запустить панику — и они НЕ одинаковые:**

| Чем запускаешь | Что выполняется | Дополнительно |
|---|---|---|
| `panic now` или хоткей `cmd+alt-p` | `panic now` | отмонтировать тома, очистить буфер, запереть экран |
| Пункт лаунчера `2) ПАНИКА` | `panic now --hard` | всё выше **плюс** убить облачные демоны и вычистить Recents |
| GUI (Paranoid Bar), двойное ⌃⌥⇧P | `panic now --hard` | то же, что у лаунчера |

Варианты с `--hard` тщательнее — и разрушительнее: убитый демон Dropbox/iCloud так и
останется мёртвым, пока не запустишь его сам. Запусти `panic status` один раз, чтобы
увидеть, что именно каждый из них сделает на твоей машине.

GUI раздаётся подписанным и нотаризованным `.dmg` — как скачать и проверить, написано в
[README.ru](README.ru.md#приложение-для-macos-меню-бар).

**6. Сделай резервную копию — по частям.**

```bash
seedsplit split
```

Команда сама попросит секрет и прочитает его без эха (в scrollback ничего не остаётся);
по Enter — готово. Можно и из файла — `seedsplit split --file ~/secret.txt` — или из пайпа,
тогда промпта не будет.

Режет фразу на доли по схеме Шамира — например, 2-из-3: любые две восстанавливают,
меньше порога — не говорят о самом секрете ничего. Доли печатаются в терминал —
перепиши их и **закрой это окно терминала** (scrollback со всеми долями — снова
единая точка отказа). Разнеси по разным местам: дом, банковская ячейка, доверенный
человек. `seedsplit combine` собирает обратно. Сейф — рабочая копия; доли — копия
на случай катастрофы.

Чаще всего ломается именно ручное переписывание доли, поэтому каждая доля несёт поле parity:
`combine` чинит **до двух байт с опечаткой на долю** и говорит об этом после того, как секрет
сошёлся. Дальше двух байт починка может и не выйти — но неверный секрет ты не получишь в любом
случае: за это отвечают контрольная сумма доли и 128-битный tag нагрузки, а не сама починка.
Опечатку в короткой голове строки (`setid`/`T`/`x`) и пропущенный символ, сдвигающий остаток,
он не чинит вовсе — такую долю нужно переписать с бумаги заново.

Весь цикл: **check → vault → vaultwatch → panic → seedsplit**.
Закрой сейф (`securetrash vault close`), когда закончил; открой в следующий раз,
когда секрет реально понадобится — а хорошей seed phrase это почти никогда.

## Инструменты по отдельности

### 1. securetrash — стереть файлы и шифрованный сейф

**Когда:** надо удалить чувствительный файл всерьёз или хранить секреты в зашифрованном
контейнере.

```bash
securetrash check              # честный вердикт: какие гарантии реальны на твоём диске
securetrash vault create [size]  # создать шифрованный сейф (size — потолок, напр. 5g / 500m)
securetrash vault open         # открыть (смонтировать) сейф
securetrash vault close        # закрыть сейф
securetrash vault reset [size]   # очистить: crypto-shred текущего + новый пустой сейф (см. ниже)
securetrash vault destroy      # снести сейф целиком (необратимо)
securetrash vault destroy-old  # crypto-shred контейнера, оставшегося от прерванного reset
securetrash vault status       # состояние сейфа
securetrash shred ~/secret.pdf # стереть один файл

# Стереть несколько разом — перечисли пути, подай glob или целую папку (один запрос
# подтверждения на весь список):
securetrash shred a.pdf b.docx c.key   # явный список файлов
securetrash shred ~/Out/*.pdf          # все .pdf в папке Out (glob разворачивает shell)
securetrash shred ~/Out/*              # все файлы в Out, саму папку оставить (скрытые dotfiles не возьмёт)
securetrash shred ~/Out                # вся папка Out целиком, рекурсивно
```

**Главное:** на SSD затирание (`rm -P`) гарантий не даёт. Реальная защита — держать
секреты внутри `vault` (он шифрованный), а «удаление» = уничтожение ключа. Именно это
`check` объясняет на твоём железе. `securetrash shred` на SSD — best-effort, а не гарантия:
чтобы была гарантия, файл должен был лежать в сейфе, который ты потом `destroy`.

**Открытый сейф в Finder.** После `vault open` том виден как обычный диск: в боковой
панели Finder («Места») и на рабочем столе, окно открывается само. Закрыл окно — том
никуда не делся: открой его снова из боковой панели, или командой `open /Volumes/SecretVault`,
или в Finder через `Cmd+Shift+G` → `/Volumes/SecretVault`. «Извлечь» том из Finder
размонтирует его — это тот же `vault close`, секреты снова зашифрованы на диске. Если
нужна максимальная приватность (том вне боковой панели и рабочего стола) — открывай с
`ST_VAULT_HIDDEN=1 securetrash vault open`; тогда вернуть окно можно только командой `open`.

**Как класть файлы в сейф — создавать внутри, а не переносить внутрь.** Это самое частое
заблуждение, и оно съедает всю гарантию. Смонтированный сейф — **отдельный том**, поэтому
перетаскивание файла туда всегда идёт как *скопировать, потом удалить оригинал*; зажатый
`Cmd` тут ничего не меняет. И главное: след на диске оставило **не** перемещение. Он появился
в тот момент, когда файл вообще впервые оказался на диске — скачался, сохранился из редактора,
пришёл в мессенджере. С этой секунды его открытые данные лежат в блоках внешнего диска, и
перенос в сейф ничего к этому не добавляет и ничего не убирает.

Поэтому единственный путь, при котором открытой копии снаружи не было никогда, — **создавать
файл сразу внутри открытого сейфа**: `vault open`, дальше сохраняй/создавай прямо в
`/Volumes/SecretVault/`. Именно так устроен `ghostdraft` для текста — черновик живёт на
RAM-диске или в сейфе и намеренно отказывается писать в `/tmp`.

Если секретный файл уже существует снаружи — перенеси его в сейф и затем `securetrash shred`
оригинал. Но относись к этому как к *снижению риска*, а не как к гарантии: на SSD надёжно
перезаписать конкретный файл нельзя (wear leveling, TRIM, copy-on-write), о чём `check` и
говорит прямым текстом.

**Что всё ещё может хранить копию после shred:**

- **Снимки.** Локальный снимок APFS (macOS — Time Machine, а также Carbon Copy Cloner, Arq и
  подобные) или теневая копия VSS (Windows), сделанный пока файл лежал снаружи, хранит его
  **целиком**, а не только имя. `shred` туда не дотянется, и убрать из снимка один файл нельзя —
  только снимок целиком. На macOS: `tmutil listlocalsnapshots /`, затем
  `sudo tmutil deletelocalsnapshots <дата>`, где `<дата>` — часть `YYYY-MM-DD-HHMMSS` из имени
  (не имя целиком). На Windows из консоли администратора: `vssadmin list shadows`, затем
  `vssadmin delete shadows /for=C: /oldest`. `securetrash check` и заметка после каждого `shred`
  показывают, сколько снимков есть.
- **Бэкапы и синхронизация.** Time Machine на внешнем диске, история версий iCloud/Dropbox —
  полные копии, о которых локальный `shred` ничего не знает.
- **Имена и миниатюры.** `.DS_Store`, «Недавние», индекс Spotlight и списки «Открыть недавние»
  в приложениях помнят имена и пути; кеш миниатюр QuickLook помнит отрисованную *картинку*
  документа.

**Что именно и от чего закрывает — здесь важна точность.** Шифрование всего диска (FileVault /
BitLocker) закрывает ровно один из этих каналов: остаточные блоки удалённого оригинала. С ним
вынули диск, читают на другой машине — получают шум; это гарантия сильнее любого затирания, и
`check` показывает, включено ли оно. Но против остальных трёх оно **не помогает**: снимок на
маке с FileVault читает любой, кто может войти в систему, а история версий в облаке лежит вообще
не на твоём диске.

Все каналы разом закрывает только одно — не давать файлу существовать вне сейфа с самого начала.
Ровно поэтому правило в начале раздела звучит как «создавай внутри», а не «переноси внутрь». И
поэтому же снимки не угрожают тому, что уже лежит в сейфе: снимок захватывает контейнер
шифротекстом.

**Очистить сейф = гарантированно стереть всё содержимое.** Пункт `Сейф ▸ 2) Очистить`
(он же `securetrash vault reset`) выбрасывает текущий контейнер и создаёт на его месте
новый **пустой** сейф. Зачем так грубо: перезаписать файлы внутри живого сейфа на SSD —
только best-effort, тот же ключ контейнера продолжает расшифровывать остаточные блоки,
которые SSD мог не отдать поверх. Единственная настоящая гарантия безвозвратности —
уничтожить ключ контейнера; поэтому «очистить» = уничтожить ключ + создать заново. Рабочий
(уже пустой) сейф остаётся на месте — можно сразу работать дальше. Это ровно сценарий
«накопил файлы → гарантированно стёр всё → продолжаю». securetrash спросит `yes` и пароль
для нового сейфа.

**«Очистить» — это два разных действия, называемых одним словом.** Пункт лаунчера
`Сейф ▸ 2) Очистить` — это `securetrash vault reset`, crypto-shred зашифрованного
**контейнера**. Команда `securetrash empty` — совсем другое: она чистит `~/SecureTrash`,
обычную папку-приёмник, перезаписывая файлы на месте — best-effort, а на SSD вообще без
гарантий. Нужна гарантия — нужен вариант с сейфом.

**Контейнер, оставшийся от прерванного reset.** Если `vault reset` прервали уже после того,
как он отставил старый контейнер в сторону, тот остаётся на диске рядом с сейфом, и любая
команда `vault` о нём сообщает — на macOS это `SecureVault.sparsebundle.old`, на Windows
`SecureVault.old.vhdx` (там суффикс идёт перед расширением, иначе система не опознала бы
контейнер).

В нём твои прежние данные, поэтому автоматически он не удаляется **никогда**: возможно, это
единственная копия. Забрать данные на macOS: `hdiutil attach ~/SecureVault.sparsebundle.old`,
скопировать нужное, затем **извлечь том** (Finder или `hdiutil detach`). На Windows:
`Mount-DiskImage -ImagePath $HOME\SecureVault.old.vhdx`, разблокировать
`manage-bde -unlock <буква>: -Password`, скопировать, затем `Dismount-DiskImage`.

И только когда контейнер размонтирован, `securetrash vault destroy-old` делает crypto-shred.
Пока он смонтирован, команда отказывается: снести backing store живого расшифрованного тома —
ровно та беда, ради предотвращения которой инструмент и существует.

**Удалить сейф целиком.** `securetrash vault destroy` сносит контейнер
(`~/SecureVault.sparsebundle`) и делает ему crypto-shred: ключа больше нет, иконка исчезает из
боковой панели и с рабочего стола. **Это необратимо — всё, что внутри, пропадает навсегда.**
Сначала скопируй наружу то, что нужно, и закрой окна Finder и приложения, которые держат том:
если размонтировать не удастся, `destroy` откажется работать и оставит контейнер нетронутым.

**Размер сейфа.** При создании (и при очистке→пересоздании) лаунчер спросит потолок
размера. Это **лимит, а не резерв**: контейнер тонкий (sparsebundle на macOS, VHDX на
Windows) и растёт по мере добавления файлов — пустой почти не занимает места. Оставить
пусто = по умолчанию (1 ГБ). На macOS формат вроде `5g` / `500m`; на Windows — в мегабайтах
(напр. `5120`).

### 2. vaultwatch — сторож открытого сейфа

**Когда:** открыл сейф и не хочешь, чтобы он висел открытым и попал в Spotlight,
Time Machine или облако. Обычно работает сам через хуки securetrash.

```bash
vaultwatch install-hooks                       # один раз: связать с vault open/close
vaultwatch start --ttl 30m /Volumes/MyVault    # вручную: охрана + авто-закрытие через 30 мин
vaultwatch stop /Volumes/MyVault               # снять охрану и показать отчёт
vaultwatch status                              # какие сейфы под охраной сейчас
```

**Главное:** после `install-hooks` про него можно забыть — `securetrash vault open`
сам поднимет охрану, `close` снимет.

### 3. panic — всё с экрана, сейчас

**Когда:** кто-то подошёл, надо мгновенно убрать всё с глаз.

```bash
panic now            # закрыть сейфы, отмонтировать тома, очистить буфер, заблокировать экран
panic now --hard     # то же + убить облачные демоны
panic hotkey install # повесить на глобальный хоткей (cmd + alt - p), см. README panic
```

**Главное:** `panic` прячет и блокирует, но данные не уничтожает. Для настоящей скорости
повесь его на глобальный хоткей через `panic hotkey`.

### 4. ghostdraft — черновик без следов на диске

**Когда:** надо набросать секретный текст (пароль, seed, заметку), который не должен
осесть на диске.

```bash
ghostdraft new              # эфемерный черновик; на выходе — стереть + чистка следов редактора
ghostdraft new --clipboard  # то же + на выходе положить результат в буфер обмена (с подтверждением)
pbpaste | ghostdraft pipe   # показать буфер в терминале, не записывая на диск
```

**Сначала пойми, что тебе нужно — это две разные задачи:**

- **Написал секрет → отдал/вставил один раз → пусть исчезнет.** Это `ghostdraft new`.
  Файл живёт внутри открытого `vault` (или на RAM-диске, если сейфа нет), а на выходе из
  редактора — стирается. Записывать сюда ключи «на память» бессмысленно: после выхода их
  нет. Чтобы успеть забрать результат — см. `--clipboard` ниже.
- **Держать ключи и копировать их в приложения снова и снова.** Это НЕ `ghostdraft new`
  (он шредит на выходе). Заведи обычный файл **внутри открытого сейфа** —
  `/Volumes/SecretVault/keys.txt` — редактируй и копируй когда нужно, а `securetrash vault
  close` снова зашифрует его на диске. Это твоё постоянное зашифрованное хранилище.

**Скопировать секрет один раз (через лаунчер):**

1. `paranoid` → `4` (Блокнот) → `1) заметка`.
2. Откроется редактор (`vim` с мягким переносом — длинный ключ не уезжает за край и не
   рвётся). Впиши секрет и выйди. **Как выйти из vim (надёжный способ):** нажми **`Esc`**,
   затем набери **`ZZ`** — сохранить и выйти, или **`ZQ`** — выйти **без** сохранения
   (выбросить черновик). Привычные **`:wq`** (сохранить) / **`:q!`** (выбросить) тоже
   работают — `Esc`, потом двоеточие, команда, `Enter`. Подсказка всегда висит внизу экрана.
   > ⚠️ Клавиши **F2/F3** (сохранить/отменить) тоже назначены, но **некоторые терминалы
   > (например Warp) их перехватывают** и до vim они не доходят — поэтому полагайся на
   > `Esc` → `ZZ`/`ZQ`, а не на F-клавиши.
3. ghostdraft спросит подтверждение на копирование в буфер — ответь `yes`.
4. Вставь секрет в нужное приложение (`Cmd+V`).
5. Через ~20 секунд буфер очистится сам — но только если ты за это время его не перезаписал
   (скопировал что-то другое). Сам черновик к этому моменту уже стёрт.

То же напрямую, без меню: `ghostdraft new --clipboard`.

**Главное:** ghostdraft не обещает «ноль следов» там, где их оставляет сама ОС (swap,
scrollback терминала, у `vim` — `~/.viminfo`) — он это честно перечисляет на выходе.
Дефолтный редактор `vim -i NONE` как раз отключает `~/.viminfo` и добавляет видимую
строку-подсказку с F2 (сохранить и выйти) / F3 (отменить) — чтобы новичок не застрял в
`-- INSERT --`. Эти маппинги только у дефолтного `vim`; если задал свой `$EDITOR` — его
не трогаем (на Windows дефолт — `notepad`). Буфер обмена опасен сам
по себе (менеджеры буфера, Universal Clipboard в iCloud) — потому копирование явное, с
подтверждением, и с авто-очисткой.

### 5. seedsplit — разрезать секрет на доли (схема Шамира)

**Когда:** есть seed-фраза, мастер-пароль или приватный ключ, и не хочешь, чтобы один
носитель (бумажка, флешка, бэкап) был единой точкой провала. Режешь на N частей так, что
любые **T** из них восстанавливают секрет, а T−1 не дают о нём **ничего**.

```bash
# Разбить seed на 5 долей, порог 3 (любые 3 из 5 восстановят). Секрет — через stdin:
printf '%s' "legal winner thank year wave ..." | seedsplit split -n 5 -t 3
# → 5 строк вида SSS2-<setid>-3-1-<hex>-<chk>. Разнеси их по разным местам.

# Собрать обратно из любых 3 долей (по строке на долю):
seedsplit combine < мои-3-доли.txt
# или: pbpaste | seedsplit combine
```

**Главное:**
- Секрет подаётся через **stdin или `--file`**, не аргументом (аргумент виден в `ps`).
- Каждая доля несёт контрольную сумму — опечатку при наборе доли поймает.
- Доли от разных секретов или повреждённые — `combine` честно откажет, а не вернёт мусор
  (внутри зашита проверка целостности).
- ⚠️ Совместимости со SLIP-39 и аппаратными кошельками пока нет — это собственный формат.
  Доли безопасны ровно настолько, насколько надёжно ты их хранишь и разносишь.

## Типичный сценарий

```bash
securetrash vault open    # открыл сейф — vaultwatch сам встал на охрану
ghostdraft new            # набросал секрет, он лёг внутрь сейфа, следов снаружи нет
# ...работаешь...
panic now                 # кто-то подошёл — мгновенно всё закрыл и заблокировал экран
```

## Подсказки

- Любой инструмент без аргументов или с непонятной командой печатает свою справку.
- `securetrash check` стоит запустить первым: он объяснит, что на твоём железе реально
  защищает, а что нет.
- Не помнишь команды — открой `paranoid` и работай через меню.
- Вывод по умолчанию английский. Русский включает `ST_LANG=ru` — на одну команду
  (`ST_LANG=ru paranoid`) или на всю сессию (`export ST_LANG=ru`). Русская системная локаль
  подхватывается сама; `ST_LANG=en` возвращает английский. Именно поэтому дашборд в этом
  документе показан по-русски.
