## Монорепо (2026-08-13, s37)

Пять тул-репозиториев слиты в этот репозиторий как subtree (история сохранена);
пер-тул репозитории **архивированы** — read-only, но их страницы, теги и релизные
ассеты продолжают отдаваться. Что из этого следует:

- **Версионирование остаётся независимым**, per tool. Схема тегов —
  `<tool>-vX.Y.Z` (`securetrash-v0.5.7`, …); голые `vX.Y.Z` в монорепо не живут,
  единственное исключение — уже существующий `gui-v0.1.0`.
- **Схема ассетов и URL (принята s37, вторая волна).** Релиз привязан к тегу,
  ассеты сохраняют ПЛОСКИЕ имена (`<tool>`, `install.sh`, `<tool>.ps1`,
  `install.ps1`, `SHA256SUMS`, `SHA256SUMS.sig`) — коллизий между тулами нет,
  потому что каждый URL включает тег. **`releases/latest` не используется
  нигде**: в монорепо это «последний релиз ЛЮБОГО тула», и
  `latest/download/install.sh` отдал бы ассет чужого инструмента. Все ссылки —
  только пиннутые: `releases/download/<tool>-vX.Y.Z/<asset>`.
- **Версия по умолчанию вшита в код и заперта гейтами.** Дефолт живёт в трёх
  местах — `<TOOL>_VERSION_DEFAULT` в `<tool>/install.sh` и
  `<tool>/windows/install.ps1`, карта `tool_version_for()` в умбреллном
  `install.sh` — плюс пин в `verify-releases.sh`. `release.yml` перед подписью
  проверяет, что все четыре равны версии тега (и что инсталлеры не качают из
  архивных репо); рассинхрон = релиз не выйдет.
- **Порядок нарезки релиза тула:** bump `VERSION` в скрипте и `.ps1` → запись в
  `CHANGELOG.md` (ссылка на монорепо-тег; исторические compare-ссылки на
  архивные репо не трогаем) → обновить все четыре дефолта выше → дождаться
  зелёного `ci-<tool>.yml` (release.yml Windows-матрицу не гоняет) → тег
  `<tool>-vX.Y.Z` → release.yml тестирует на коммите тега, подписывает и
  публикует → пост-релизный `chore(formula)`: URL формулы на tarball
  монорепо-тега + свежий sha256 (формула не может нести хеш тарбола, в котором
  лежит сама, — поэтому всегда после тега).
- **Гейт секрета:** `RELEASE_SIGNING_KEY` (тот же ed25519-ключ; офлайн-бэкап в
  securetrash vault) должен лежать в secrets ЭТОГО репозитория — руки Mr.Di.
  Без него release.yml честно падает, неподписанных релизов не бывает.
- **Старые релизы** (`v0.5.6` / `v0.1.14` / `v0.1.15` / `v0.1.18` / `v0.5.5`)
  остаются в архивных репозиториях и продолжают отдаваться — сохранённые у
  пользователей старые `install.sh` работают.
- **CI** — пер-тул workflow `ci-<tool>.yml` с paths-фильтром; бейджи в README
  тулов указывают на них. Maintainer-режим умбрелльного `install.sh` теперь
  только по `PT_DEV=1` (в монорепо исходники есть у каждого клона — автовключение
  убило бы verify-then-run для публики).
- Vendoring `lib/common.sh` идёт из соседнего каталога `securetrash/` этого же
  репо (SHA-пин содержимого сохранён), сеть больше не нужна.

`.github/`), прогона не будет, и его нужно поднять вручную:

```bash
gh workflow run ci-<tool>.yml --ref main   # дождаться зелёного, потом ставить тег
```

Бандл и `.dmg` — build-артефакты, в git не лежат (`.gitignore`), пересобираются из исходника.
Фон образа и `.icns` — единственные ассеты, они в git есть; растеризатора SVG на машинах нет,
оба нарисованы разово на CoreGraphics (генераторы, как и у `assets/logo.png`, не хранятся).
**Windows-трей не подписан:** Authenticode требует сертификат коммерческого CA — отдельная
покупка, Apple-аккаунтом не покрывается. Остаётся хвостом вместе с шимом под Windows.
