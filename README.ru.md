Пять небольших консольных инструментов вокруг того, как живёт секрет — seed-фраза,
пароль, ключ: написать, не оставив копий; хранить зашифрованным; стеречь, пока открыт;
мгновенно спрятать всё по тревоге; разложить на бумажные доли, которым не страшна
опечатка. Каждый инструмент — один читаемый файл (чистый Bash на macOS, порт на
PowerShell для Windows) без зависимостей во время работы; все пятеро живут в этом
репозитории. **Это не менеджер паролей** — это локальный набор для тех немногих
секретов, утечку которых уже не отменить. Без облака, без телеметрии, без обещаний,
которых нельзя сдержать.

## Установка

Одна команда ставит все пять инструментов и лаунчер в `~/.local/bin`:

```bash
git clone https://github.com/Di-kairos/paranoid-tools
cd paranoid-tools
bash install.sh            # ставит все 5 + лаунчер paranoid
```

Каждый инструмент тянется из своего **подписанного релиза** по правилу «сначала проверь,
потом запускай»: установщик сверяет подпись Ed25519 над `SHA256SUMS`, затем контрольную
сумму `install.sh` самого инструмента и только после этого его запускает — а тот, в свою
очередь, проверяет бинарь до установки. Всё, что приходит из сети, проверено раньше, чем
что-то выполнится (верхний `bash install.sh` ты запускаешь руками, прочитав его).

Есть также подписанное и нотаризованное **[приложение для macOS](#приложение-для-macos-меню-бар)**
и **[путь для Windows](#windows)** (PowerShell 7). Homebrew пока закрывает `securetrash`
(`brew install Di-kairos/tap/securetrash`).

обоих языках. Changelog'и и `docs/RELEASE-STATE.md` написаны по-русски: это заметки к
релизам, и то же самое по существу изложено в английских доках. `git log` — целиком
английский.

> **Windows.** У всех пяти есть порт на PowerShell (beta, логика покрыта Pester на CI; доли
> seedsplit совпадают с macOS-сборкой байт в байт). То, на чём инструменты стоят в macOS —
> Spotlight, Time Machine, `launchd`, `hdiutil`, — переложено на windows-аналоги (Windows
> Search, VSS, Task Scheduler, BitLocker). Где аналог неполный, инструмент говорит об этом
> сам.

## Не доверяй — проверяй

Релизы подписаны Ed25519 · во время работы не нужно ничего, кроме системы (два исключения
включаешь сам — они названы в заметках к установке) · каждый инструмент помещается в один
читаемый файл · shellcheck-clean. Границы названы прямо — раздел *Scope & limitations*
есть у каждого инструмента. **Стороннего аудита у нас нет, и мы его не заявляем**; но
весь код — это ~4 800 строк шелла в семи скриптах, так что прочитать его самому — пара
вечеров, а не проект.

**Проверь релизы сам.** `bash verify-releases.sh` скачивает опубликованный релиз каждого
инструмента и сверяет подпись Ed25519 и контрольную сумму с ключом, вшитым в этот
репозиторий. Ничего не устанавливает, из внешнего нужны только `curl` и `ssh-keygen`.
Это и есть заголовок раздела в исполняемом виде. Что и как тестируется —
[docs/TESTING.md](docs/TESTING.md).

**Криптография говорит о себе честно.** `seedsplit` реализует Шамира над GF(256) на
чистом Bash — реализация наша собственная, **независимого аудита не проходила**, а
умножение через таблицы log/antilog не constant-time (так и написано в его README).
Что стоит вместо аудита сегодня: CI на каждый push дифференциально сверяет её с
независимой Python-реализацией — доли, разложенные здесь, обязаны собираться там и
наоборот, — плюс property-тесты порога, смешения наборов и RS-починки опечаток.
Граница доверия написана там, где её можно прочитать:
[seedsplit → Scope & limitations](seedsplit/README.ru.md#scope--limitations).

Подходит ли этот набор под твою ситуацию — и от чего он **не** спасёт — разобрано в
**[модели угроз](THREAT-MODEL.ru.md)**. Он закрывает промежуток между менеджером паролей,
шифрованием диска и бумажным бэкапом — но не заменяет ни одного из них.

### Рубильники и края установки

Опасные рубильники названы здесь, а не оставлены тебе на самостоятельную находку.
`ALLOW_UNSIGNED_LEGACY=1` осознанно опускает проверку до одной контрольной суммы — он
существует ради релизов, выпущенных до подписи. `PT_ALLOW_PARTIAL=1` даёт закончить
установку, когда часть инструментов не встала. Мейнтейнер может поставить всё прямо из
рабочей копии через `PT_DEV=1` — этот путь минует проверку релизов и говорит об этом в
выводе; без флага любая установка идёт через подписанные релизы, что бы ни лежало в
клоне. В Windows-установщиках тот же рубильник называется `PT_ALLOW_HASH_ONLY=1`.
«Ноль зависимостей» знает два исключения, и оба включаешь ты сам: `panic hotkey` требует
`skhd`, `seedsplit -p` — `openssl` (в README этих инструментов сказано). Плюс сам
Windows-порт работает на PowerShell 7 — единственное требование к платформе. Закрепить
версию: `PT_ST_VERSION` / `PT_VW_VERSION` / `PT_PANIC_VERSION` / `PT_GHOSTDRAFT_VERSION`
/ `PT_SEEDSPLIT_VERSION` (написанное иначе игнорируется молча). Сменить каталог —
`PT_DEST=/usr/local/bin`.

**Linux.** `install.sh` там отказывается работать, и это решение, а не недосмотр:
securetrash, vaultwatch, panic и ghostdraft построены на примитивах macOS (`hdiutil`,
`fdesetup`, `mdutil`, `tmutil`, `launchd`), а линуксовых замен с той же честностью насчёт
гарантий у них нет. Порт на LUKS и systemd — это другой инструмент, а не ещё один флаг.
Исключение одно — `seedsplit`: чистая арифметика поверх POSIX-утилит, работает везде,
где есть Bash.

Нужен один инструмент, а не все? Или хочется пройти каждый шаг руками? В README каждого
есть отдельный пример установки с проверкой и короткая однострочная форма. Учти разницу:
те установщики по умолчанию кладут бинарь в `/usr/local/bin` и просят sudo, а этот — в
`~/.local/bin`. Если пользоваться обоими, получатся две копии, и какая запустится, решит
`PATH`. Держи их в одном месте: через `PT_DEST` или через переменную назначения самого
инструмента.

### Приложение для macOS (меню-бар)

`ParanoidBar.app` — обёртка над теми же пятью CLI: она их запускает, а не заменяет, и без них
бесполезна, так что сначала поставь инструменты командой выше. Образ лежит в
[GUI-релизе](https://github.com/Di-kairos/paranoid-tools/releases/tag/gui-v0.1.0): открой его и
перетащи приложение на `/Applications`.

```bash
curl -LO https://github.com/Di-kairos/paranoid-tools/releases/download/gui-v0.1.0/ParanoidBar-0.1.0.dmg
shasum -a 256 ParanoidBar-0.1.0.dmg
# da80707bb0e63a9deb3a05a0387ef64b75db6b6d2c28c25a5170d293b445b00a
```

Приложение подписано сертификатом Developer ID и нотаризовано Apple, тикет вшит в образ —
Gatekeeper пропускает его без плясок с «неустановленным разработчиком», в том числе офлайн и на
машине, которая видит его впервые. Не верь на слово — проверь до запуска:

```bash
spctl --assess --type open --context context:primary-signature ParanoidBar-0.1.0.dmg
#   → accepted, source=Notarized Developer ID
xcrun stapler validate ParanoidBar-0.1.0.dmg
```

Честная оговорка: Ed25519-подписи `SHA256SUMS`, как у релизов CLI, у образа нет. Тем ключом
подписывается то, что собирает CI, а образ обязан собираться там, где хранится ключ Apple.
Цепочка доверия здесь — подпись Apple, вшитый тикет, контрольная сумма выше и открытый исходник:
`gui/macos/build.sh` собирает тот же образ. Значка в Dock у приложения нет — это агент
меню-бара, иконка появляется справа сверху. Нужна macOS 13+.

**Трей для Windows** пока не подписан (Authenticode — отдельная покупка у коммерческого CA,
аккаунтом Apple не покрывается), поэтому раздаётся только исходником — запуск из клона, см.
[gui/README.md](gui/README.md).

### Удаление

```bash
bash install.sh --uninstall   # снять все инструменты и лаунчер
```

### Windows

Однострочная установка выше — только для macOS. На Windows это несколько коротких шагов,
и вот они с нуля. Шаги **1–2 делаются один раз**, шаг 3 повторяется для каждого инструмента.

**1. Поставь PowerShell 7.** Ставить и запускать поддерживается только на PowerShell 7
(`pwsh`); встроенный в Windows PowerShell 5.1 официально не поддерживается. В любом терминале
(нажми `Win`, набери «PowerShell», Enter):

```powershell
winget install --id Microsoft.PowerShell -e
```

Закрой это окно и открой из меню «Пуск» **«PowerShell 7»**. Проверь версию:

```powershell
pwsh --version      # должно напечатать «PowerShell 7.x»
```

**2. Поставь Git** — им скачиваются инструменты, — затем открой новое окно PowerShell 7:

```powershell
winget install --id Git.Git -e
```

**3. Поставь инструмент.** Все пять лежат в этом репозитории — клонируй один раз и ставь
те, что нужны. Пример на `securetrash` (вместо каталога подставь `vaultwatch`, `panic`,
`ghostdraft` или `seedsplit`):

```powershell
git clone https://github.com/Di-kairos/paranoid-tools
cd paranoid-tools/securetrash
pwsh -File windows/install.ps1
```

`install.ps1` скачивает подписанный релиз, **сверяет подпись Ed25519 и контрольную сумму
до того, как что-то установить** (не сошлось — ставить откажется), кладёт инструмент в
`%LOCALAPPDATA%\Programs\securetrash` и сам прописывает его в PATH.

**4. Пользуйся.** Открой **новое** окно PowerShell, чтобы подхватился изменённый PATH, и
вызывай инструмент по имени:

```powershell
securetrash version
securetrash --help
```

Шаг 3 повтори для каждого нужного инструмента. У меню-лаунчера `paranoid` тоже есть
windows-версия: из корня клона запусти `pwsh -File windows/paranoid.ps1`.

> **Бета.** Логика windows-портов покрыта тестами на CI, но на живом железе они пока обкатаны
> мало — попробуй сперва на данных, которых не жалко, и только потом доверяй настоящие секреты.

### Подпись релизов — что она закрывает на самом деле

**Коротко:** подпись защищает канал доставки, но один ключ на все пять инструментов — общая
точка риска.

Релизы подписаны **одним ключом Ed25519** на все пять инструментов. Размен здесь такой:
если этот ключ утечёт — через секрет в GitHub Actions или через вредоносную правку
`release.yml`, — подделать подписанный релиз можно будет сразу для **всей экосистемы**,
а публичный ключ вшит в установщики, и отозвать его на месте сегодня нечем. От
атакующего, который держит только канал доставки — зеркало, CDN, MITM, — подпись всё
равно защищает, а это и есть обычный случай. Переход на **отдельные ключи по
инструментам или подпись через OIDC с описанной ротацией и отзывом** запланирован, но
пока не выпущен. Нужна максимальная гарантия — закрепи точную версию и сверь её
`SHA256SUMS` с независимой копией.

### Обновление

Команды `update` нет: обновиться — значит **запустить установщик заново**. Он тянет
последний подписанный релиз каждого инструмента и переписывает бинарь на месте:

```bash
cd paranoid-tools
git pull            # обновить клон (лаунчер + установщик)
bash install.sh     # переставить все инструменты на последние подписанные релизы
```

Версию инструмента показывает `securetrash version` (или `--version` у любого другого).
Если обновление поменяло поведение уже работающего инструмента — скажем, `securetrash vault`
теперь монтирует том видимо в Finder, — открытая сессия продолжит жить на старом коде.
Переоткрой её: `securetrash vault close`, потом `securetrash vault open`.

**Как узнать о новой версии.** Телеметрии нет, наружу ничего не уходит, а значит новая версия
сама тебя не найдёт — искать её тебе. Дешевле всего и без ущерба приватности: на GitHub нажми
**Watch ▸ Custom ▸ Releases** у [paranoid-tools](https://github.com/Di-kairos/paranoid-tools) —
GitHub пришлёт письмо на каждый релиз. Бейджи **Версия** в таблице всегда показывают текущий
релиз; сравни с тем, что отвечает локальный `<tool> version`. Ставил через Homebrew —
`brew upgrade` подтянет новую формулу. Лаунчер `paranoid` тоже умеет показывать на дашборде
строку «доступно обновление», если ты это включишь — см. [Лаунчер](#лаунчер).

## Лаунчер

`paranoid` — интерактивный лаунчер поверх пяти команд: дашборд состояния плюс меню. Чистый
Bash и ни одной зависимости, как и у инструментов, которыми он управляет. Меню разложено по
подменю — **Сейф** (открыть/закрыть · очистить · уничтожить · сторожить), **Блокнот**
(ghostdraft), **Секреты** (seedsplit), — а *Статус* и *ПАНИКА* в одно нажатие оставлены
наверху. **Очистить** делает crypto-shred содержимого сейфа и выдаёт новый пустой: на SSD
это настоящая гарантия, в отличие от затирания файлов на месте.

<img src="assets/dashboard.svg" alt="Лаунчер paranoid: дашборд состояния и меню поверх пяти инструментов" width="560">
</div>

Своих секретов лаунчер не хранит и своей криптографии не добавляет — он запускает
установленные инструменты и показывает их вывод как есть, вместе с *Scope & limitations* и
вердиктами `check`. Уточним, что именно значит «подписано»: подпись проверяется **при
установке**. Дальше и лаунчер, и GUI просто зовут `securetrash`, `panic` и остальных по
имени — то есть то, что найдёт твой `PATH`, — и заново ничего не проверяют. Кто может писать
в каталог, стоящий в `PATH` раньше, тот может положить туда что-то другое, и ни один
инструмент здесь этого не заметит. Запуск без аргументов:

```bash
paranoid          # открывает дашборд и меню
```

Скажем честно: лаунчер сделан для удобства, а не ради скорости в ту самую минуту. Мгновенная
тревога на всю систему — это `panic hotkey install`, глобальный хоткей через skhd (см. README
у panic). Открытый сейф всегда помечен как «под угрозой». Зеркало на PowerShell тоже готово —
`windows/paranoid.ps1` (beta): запусти `pwsh -File windows/paranoid.ps1` или положи в PATH
под именем `paranoid`. Оно управляет теми же пятью портами.

**Проверка обновлений — по желанию.** По умолчанию выключена: пока не попросишь, дашборд к
сети не обращается. Задай `PARANOID_UPDATE_CHECK=1`, и он добавит строку *«доступно
обновление»*, когда у установленного инструмента появится более свежий подписанный релиз.
Это единственный сетевой вызов лаунчера: один запрос на инструмент к GitHub
`releases/latest` — по редиректу, без API-ключа, без телеметрии, с кэшем на сутки. Включить
на одну сессию — `PARANOID_UPDATE_CHECK=1 paranoid`; чтобы держать постоянно, пропиши
переменную в rc-файл оболочки.

## Как это устроено

- **Один репозиторий, пять независимых инструментов.** Версии и релизы у каждого свои —
  тег `<tool>-vX.Y.Z`, собственный CI. Общий код — канонический
  `securetrash/lib/common.sh`; он вшит в текст каждого инструмента между маркерами
  `# === BEGIN vendored common (pin: <ref>) ===`. Скрипт синхронизации и проверка дрейфа на
  CI не дают копиям разъехаться — и каждый инструмент остаётся одним самодостаточным
  файлом. Ни зависимости во время работы, ни шага сборки.
- **Хуки сейфа.** `securetrash vault open/close` запускают
  `~/.securetrash/hooks/{post-open,post-close}`; через них `vaultwatch install-hooks` цепляет
  сторожа к жизни контейнера. (`panic` намеренно живёт без хуков: он обязан сработать даже
  когда больше ничего не настроено.)
- **Закон экосистемы.** Один инструмент — одна задача. Раздел *Scope & limitations* в README
  обязателен. Ложное чувство безопасности не создаём никогда.

## Как это делается

Разработка ведётся **с участием ИИ** (Claude) под управлением и ревью живого мейнтейнера.
Мы пишем это прямо, чтобы не заставлять тебя гадать по ритму коммитов — и это ничего не
меняет в истории проверок, которая никогда не строилась на доверии к автору: CI на трёх
оболочках (bash, pwsh 7, Windows PowerShell 5.1), ~900 тестов (bats + Pester), включая
known-answer векторы и дифференциальную сверку криптографии с независимой реализацией,
shellcheck-clean исходники, релизы с подписью Ed25519, которую проверяет один скрипт, и
код, который короток настолько, что его можно прочитать. Верь проверкам, а не биографии.
